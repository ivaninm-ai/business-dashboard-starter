A课堂演示 · The classroom demo

A1 打开演示 · Open it

  1. 找到文件 business-dashboard-demo.html（在项目的 dist/ 文件夹，或老师发给你的文件）。
  2. 双击，用 Chrome 或 Edge 打开。页面直接显示「BetterSpace 家居生活馆」第 1 天的概览。
    Double-click it; it opens straight into the B2C Day 1 overview.
  3. 确认页面最上方有深红色横条「教学演示 · 所有记录都是虚构的练习数据」。

已在 Windows 的 Edge 和 Chrome 中测试（直接从磁盘打开）。Firefox、Safari 应该也可以，但还没测试。页面空白时，请确认浏览器开启了 JavaScript 并且是较新版本。
Tested in Edge and Chrome on Windows from disk; Firefox and Safari not yet tested.

A4 接受一个待办，看它出现在日历上 · Accept a task

  1. 打开 待办（Tasks），选一条建议，例如「跟进 BS-001 的收款」。点「依据：BS-001」会打开那张订单。
  2. 按 接受（Accept）。建议的日期和负责人变成正式的行动日期。
  3. 按 编辑（Edit），把行动日期改成 9 月 2 日，写一条备注，按 保存（Save）。
  4. 打开 日历（Calendar）：这条待办出现在你选的日期上。再按 + 新增备注（Add note） 加一条自己的备注。

日历颜色：记录中的截止日期 已接受的待办 你的备注 ⚠ 已过报告日期的截止日期

A5 前进到第 2 天 · Advance to Day 2

按 前进到第 2 天（Advance to Day 2）。记录换成 8 月 31 日的快照，所有数字重新计算。你在第 1 天做的决定会保留（按同一个待办编号），并标着「第 1 天已决定」；第 2 天才有的建议标着「第 2 天新增」；新数据已经不支持的建议移到「已由数据解决」。

业务值得讨论的变化 · What changed
B2BBS-001 的尾款 RM 4,500 付清：逾期余额 RM 30,515 → RM 26,015，订单额不变——收款不是新订单。
B2BT001 在库 22 → 30，但全部被预留，可用仍是 0——到货不等于可卖。
B2BBS-003 原定 8 月 30 日完成：第 1 天「今天到期」，第 2 天变成逾期。新潜在客户 BC-046 没有负责人。
B2CRS-001 完成了，逾期提醒消失；但 RS-002、RS-229、RS-238 没在 8 月 30 日完成，逾期交付从 8 笔变成 10 笔。

A6 重置演示 · Reset

按 重置演示（Reset demo）…，选「只重置这个业务」或「重置两个业务」。重置后回到第 1 天，没有待办决定和备注；语言选择会保留；内置的记录永远不会被修改。

保存说明 · About saving

  • 操作只保存在这台电脑的这个浏览器里，不是备份，不会同步，也不会给别人看到。B2C 和 B2B 分开保存。
  • 换浏览器、换电脑、清除浏览器数据、关闭无痕窗口，都会从头开始。
  • 在 Chrome 和 Edge 中，同一台电脑上从磁盘打开的所有演示副本共用同一份保存状态。几个人共用电脑时，先按「重置演示」。
  • 如果浏览器不允许保存，页面会显示黄色提示；演示仍然能用，但重新载入后更改会消失。

B课后：建立和扩展你自己的版本 · Your own copy

B1 建立你自己的仓库 · Create your repository

  1. 老师发布模板后，打开模板页面，按 Use this template → Create a new repository。
  2. Owner 选你自己的账号，取个名字（例如 my-business-dashboard），创建。
  3. 下载到电脑：GitHub Desktop（Code → Open with GitHub Desktop），或 git clone。不用 GitHub 的话也可以 Download ZIP。

B2 开发环境 · Development environment

安装 Node.js 22 LTS 或更新版本（nodejs.org）。在项目文件夹打开终端：

# 第一次：安装打包工具（只有 esbuild 一个）
npm install
# 开发：打开 http://localhost:5173 ，改完文件后重新载入浏览器
npm run dev
# 核对所有数字、规则、翻译和示例分析
npm test
# 生成可以双击打开的单一文件 dist/business-dashboard-demo.html
npm run build
# 分享前：build + test
npm run check

npm 11 may warn that esbuild's install script was skipped; the build still works.

B4 动手扩展 · Four exercises

每个练习的完整代码在 docs/STUDENT_SOP.md 第 4 节。做完都要运行 npm test，再在浏览器里看一遍（中文和英文）。

新增 KPI

例如「本期服务类订单额」。B2B 第 1 天 8 月应为 RM 3,400（5 笔）——答案要自己从数据算，不能从应用里抄。

core/metrics.js → pages/overview.js → i18n/zh.js → test/

新增图表

用现成的 hbars() 或 trendChart()，颜色只用样式表里的变量。

ui/components.js → pages/*.js

新增待办规则

例如「感谢回头客」。编号必须稳定（规则:记录ID），第 1 天和第 2 天才对得上。

core/model.js → core/tasks.js → data/*/business.json

新增页面

复制一个页面文件，在 main.js 注册，在 shell.js 的菜单加一项。

ui/pages/ → main.js → ui/shell.js

B5 换成你自己的数据 · Replace the data deliberately

  1. 复制 data/betterspace-b2c/ 成新文件夹；business.json 的 id 要和文件夹名一样。
  2. 保持四个表：客户、销售（一行一个订单）、收款（对应订单）、库存快照。列名和 business.json 的对应一致；日期 2026-08-30，金额用数字。
  3. 每一天的 metadata.json 写报告日期 as_of_date。第 2 天是完整快照，不是新增几行。
  4. npm run data。记录有问题时，页面会列出问题而不显示数字。
  5. 为新数据写答案 test/expected/…（自己用试算表算），并重写或删除 src/briefs/examples.js 里对应的示例分析。

只放虚构或已匿名化的数据。npm run build 会把全部记录放进 HTML 文件，任何拿到文件的人都能读到。

B6 以后接入实时 AI 和真正的存储 · Later: live AI and real storage

实时 AI

API 密钥只能放在你自己控制的服务器上，绝不能写进网页。服务器用 buildBriefInput() 的事实 + prompts/daily_brief.md 调用 AI，用 unsupportedTokens() 核对数字后才显示，并标明模型和时间。还要改 CSP 只允许连到你的服务器。

真正的存储

所有保存都经过 createStateStore()。换成云端时用同样的函数名实现，改成 await，并考虑登录、权限、备份和隐私法。

B7 发布你自己的版本（可选）· Publish your copy

GitHub Pages：你的仓库 → Settings → Pages → Source 选 GitHub Actions → Actions → Publish site → Run workflow。网址是 https://<用户名>.github.io/<仓库名>/。
其他静态网站服务：npm run build 后上传 dist/site/index.html。

发布后任何有链接的人都能看到文件里的全部记录——只发布虚构数据。

常见问题 · FAQ

页面是空白的确认浏览器开启了 JavaScript，并且是较新版本的 Chrome、Edge、Firefox 或 Safari。
重新打开后我的操作不见了是不是换了浏览器、用了无痕窗口，或清除了浏览器数据？页面上方有黄色提示时，表示这个浏览器不允许保存。
别人的操作出现在我的演示里同一台电脑、同一个浏览器里所有演示副本共用保存状态。按「重置演示」。
示例分析和我改过的待办不一致正常：示例分析是预先写好的，描述的是原始数据，不会重新分析你的操作。
双击 src/index.html 没反应源代码要用 npm run dev 打开；双击用的是 npm run build 生成的 dist/ 文件。
npm test 说数字不对先看是哪个场景、哪个数字；修正计算代码，不要去改 test/expected/ 的答案。
