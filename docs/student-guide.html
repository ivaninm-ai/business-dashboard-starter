第 0 步

准备账号

github.com
  • 一个 GitHub 账号（免费）。还没有：到 github.com/signup 注册，并到邮箱点确认信。
  • Chrome 或 Edge 浏览器。手机也能看网站，但第 1–5 步请用电脑做。
  • 不需要：Google Cloud、信用卡、API 钥匙、服务器，也不用安装任何软件。
比喻：老师的模板像一份食谱原稿。你按 Use this template 复印一份到自己名下；之后你怎么改，都不会影响老师的原稿，也不会影响同学的那一份。
⚠️ 你的仓库和网站都是公开的：任何人都能看到里面的代码和全部记录。只放虚构的练习数据——不要放真实客户资料、密码或任何钥匙。

第 1 步

复制模板到你的账号

在 GitHub

📦 一键复制模板到我的账号 ↗

  1. 按上面的按钮，会打开 GitHub 的「从模板建新仓库」页；没登录会先叫你登录。
  2. Owner 选你自己 · Repository name 填 my-business-dashboard · Description 可以留空。
  3. 选 Public——免费的 GitHub Pages 只能发布公开仓库。Include all branches 不用勾。
  4. 按 Create repository，等几秒。

没用按钮也可以：打开老师的模板页面，按绿色的 Use this template → Create a new repository。

检查

卡住了？看不到 Use this template：先登录 GitHub。提示名字已被使用：换一个仓库名，并同步改上面的“你的仓库名”。

第 2 步

打开 GitHub Pages

你的仓库 › Settings › Pages

⚙️ 打开我的 Pages 设置 ↗

  1. 在你自己的仓库点顶部的 Settings（齿轮）→ 左边选 Pages。
  2. Build and deployment 下面的 Source，选 GitHub Actions（不是 Deploy from a branch）。选了就会保存，不用再按别的按钮。
比喻：GitHub Pages 是 GitHub 免费借你的一块展示橱窗。这一步只是告诉 GitHub：“橱窗里的东西，由我的自动流程来摆。”
检查

卡住了？看不到 Settings：你打开的多半是老师的模板，不是你自己的仓库——看左上角是不是你的用户名。

第 3 步

发布你的网站

你的仓库 › Actions

🚀 打开 Publish site ↗

  1. 点顶部的 Actions → 左边选 Publish site。
  2. 右边按 Run workflow → Branch 保持 main → 按绿色的 Run workflow。
  3. 刷新一下页面，会出现一条黄色圆点的运行记录。等 1–3 分钟，变成绿色勾就完成了。它会先自动检查（打包 + 所有测试），全部通过才会发布。
  4. 打开你的网址：https://用户名.github.io/仓库名/（第一次可能要再等 1 分钟）。
检查

卡住了？
· Actions 页面叫你启用 workflows：按 I understand my workflows, go ahead and enable them，再回到第 3 步。
· 红色叉叉，失败在 Configure Pages 或 deploy：回第 2 步，确认 Source 是 GitHub Actions，然后再 Run workflow 一次。
· 红色叉叉，失败在 Run npm run check：自动检查没通过，网站不会被改坏。刚复制的模板不应该出现这种情况；把截图发到学员群。
· 网址显示 404：等 1–2 分钟再重新载入；检查网址里的用户名和仓库名；仓库要是 Public。

第 4 步

试用你的网站

你的仪表盘网址
  1. 上方场景栏选业务：B2C 家居零售 或 B2B 办公家具。右上角可以切换 中文 / English。
  2. 打开 待办（Tasks），按一条建议的 接受（Accept），再按 编辑（Edit） 改行动日期 → 保存。
  3. 打开 日历（Calendar）：这条待办出现在你选的日期上。
  4. 按 前进到第 2 天（Advance to Day 2）：数字换成 8 月 31 日的数据，你的决定会保留。
  5. 看 示例分析（Example analysis）：它是预先写好的，不是实时 AI。
  6. 最后按 重置演示（Reset demo） 回到起点。
⚠️ 你的操作只保存在这台电脑的这个浏览器里。这不是备份：换电脑、换浏览器或清除浏览器数据，就会从头开始；别人打开你的网址，也看不到你的操作。

第 5 步

打开你自己的 Excel

你的网站 › 我的 Excel

想用自己的数字试试？你的网站可以直接读取你电脑上的 Excel。文件只在你的浏览器里读取和计算，不会上传到 GitHub 或任何地方，也不会出现在别人打开的网站上。

  1. 在你的网站上方的业务里选 我的 Excel。
  2. 按 下载 BetterSpace_B2C.xlsx（或 B2B），用 Excel 打开。保留四个工作表（Customers、Sales、Payments、Stock）的名称和第一行的列名，把下面的行换成你的记录，另存为 .xlsx。
  3. 回到网站，按 选择 Excel 文件，选你的文件。数字、待办和日历马上按你的数据计算；报告日期是文件里最新的日期。
  4. Excel 改过之后：保存，再按 重新读取 Excel。不用了就按 忘记这个文件。
工作表一定要有的列
Customerscustomer_id, customer_name
Salessale_id, sale_date, total_amount
Paymentspayment_id, sale_id, payment_date, amount
Stockitem_id, on_hand_quantity

其他列（状态、付款期限、负责人等）最好照范例保留；缺少时，用到它们的数字会留空或为零，网页会告诉你缺了哪些。

⚠️ 状态只能写 Confirmed、In Progress、Completed 或 Cancelled；日期用 Excel 日期或写成 2026-08-30；金额用数字。
⚠️ 文件会记在这个浏览器里，但这不是备份。不要在共用电脑上打开机密的真实数据。
检查

卡住了？出现「这个 Excel 文件暂时不能使用」：看它列出的第一个问题，会写明是哪个工作表、哪一行、哪一列。最常见的是工作表名称或列名被改了、状态的写法不同，或文件是 .xls / .csv（要在 Excel 里另存为 .xlsx）。

第 6 步

设定你的店名和首页

你的仓库 › Settings › Secrets and variables › Actions

不用改任何文件：在仓库的设定里加两个变量，再发布一次，你的网站就会显示你的店名，一打开就是你自己的 Excel。

⚙️ 打开我的变量设定 ↗

  1. 按上面的按钮（或在你的仓库里点 Settings → 左边 Secrets and variables → Actions → 上方的 Variables 分页）。
  2. 按 New repository variable，照下表填 Name 和 Value，再按 Add variable。第二个变量用同样方法再加一次。
    Name（照抄）Value（你填）作用
    BUSINESS_NAME你的店名，例如 小明家具店「我的 Excel」改叫你的店名：左上角和业务选单都会显示。最多 40 个字。
    START_WITHmy-excel网站一打开就是你自己的 Excel。想先看范例，就填 b2c 或 b2b。
  3. 回到 Actions → Publish site → Run workflow，重新发布。改了变量也要重新发布一次，网站才会更新。
  4. 等绿色勾，再打开你的网址，按 Ctrl + F5 强制重新载入。
比喻：变量就像店门口的招牌。换招牌不用拆店：代码一行都不动，只换设定。
⚠️ 要加在 Variables 分页，不是 Secrets。变量会写进网站，任何人都看得到：只放店名这类公开资料，不要放密码或钥匙。

以后想改：回到同一页，按变量旁边的铅笔改 Value，再发布一次。不想要了就删掉变量，再发布一次。每个访客第一次打开时会照 START_WITH；之后他们自己选的业务会记在他们的浏览器里。

检查

卡住了？发布出现红叉，失败在 Run npm run check：点开看红字，它会写明哪个变量不对，例如 START_WITH 只能是 my-excel、b2c、b2b。回到 Variables 改好，再发布一次；在那之前，网站仍是上一个正常版本。店名没变：确认 Name 全是大写英文、没有空格，而且是加了变量之后才按 Run workflow。

第 7 步

让 AI 编程助手帮你扩展

AI 编程助手

想加新功能（新指标、图表、页面），交给 AI 编程助手（例如 Claude Code）来做：把你的仓库地址给它，安装、运行和检查都让它负责，你只要看结果。

  1. 把你的仓库地址 https://github.com/用户名/仓库名 给助手，请它先读 AGENTS.md。这个文件写着不能改坏的规则：数字必须从记录算出来、报告日期固定、不联网、不放钥匙、所有文字要有中文翻译、示例分析要诚实标明。
  2. 用一句话说清楚你要什么，并要求它做完后运行全部检查、告诉你结果和没能验证的地方。例如：
    请先读 AGENTS.md。在 B2B 概览加一个「本期服务类订单额」KPI， 加上中文翻译和测试，运行全部检查， 告诉我结果，以及你没能验证的地方。
  3. 让助手把修改推送到你的仓库，然后照第 3 步 Publish site，在你的网址上看看新功能（中文和英文都看一下）。

新增指标

例如「本期服务类订单额」。B2B 第 1 天 8 月应为 RM 3,400（5 笔）——用这个数字检查助手做得对不对。

新增图表

例如「按产品的订单额」。用现成的横条图，颜色只用已有的颜色。

新增待办规则

例如「感谢回头客」。每条建议的编号要稳定，第 1 天和第 2 天才对得上。

新增页面

例如「产品」页。复制一个现有页面，再加到菜单里。

给助手看的完整技术说明在仓库的 docs/STUDENT_SOP.md。

⚠️ 不要让助手把任何 API 钥匙写进网页代码——网站是公开的，任何人都能看到。以后想接入实时 AI，钥匙必须放在你自己管理的服务器上（见 docs/STUDENT_SOP.md 第 6 节）。
检查

卡住了？发布出现红叉：把 Actions 里失败那一步的截图给助手，请它修好再推送；网站在修好之前仍是上一个正常版本。

规则与限制

要记住为什么
你的 Excel 只在你的浏览器里它在你的电脑上读取，不会上传，也不会发布到你的网站上。按「忘记这个文件」就会从浏览器删除。
本地保存不是云端备份网页上的操作只存在那台电脑的那个浏览器里；没有登录、没有同步、没有共享。
示例分析不是实时分析它是预先写好的，描述原始数据；你接受或修改待办，它不会重新分析。
你的版本可以自由使用模板用 MIT 授权：你可以修改、自己用、商用，也可以请程序员帮你扩展，只要保留仓库里的 LICENSE 文件。软件按「原样」提供，不附带任何保证。
只放虚构或匿名数据仓库和网站都是公开的，网站文件里包含全部记录。这是学习项目，不适合机密的真实业务数据。
每次修改都要重新发布改了变量、Commit 或 Push 之后，都要运行 Publish site，网站才会更新。检查没通过就不会发布。
报告日期是固定的第 1 天是 2026 年 8 月 30 日，第 2 天是 8 月 31 日，不会随今天的日期改变。
换成自己的数据要按步骤来先读 docs/STUDENT_SOP.md 第 5 节：数据格式、答案文件和示例分析都要一起更新。
