# AGENTS.md — handoff for AI coding assistants

Business Dashboard Starter: a setup-free small-business dashboard for the viewer's own Excel
workbook, and a starter for students to extend. Plain JavaScript ES modules, no framework, no
backend. It has **no built-in data**: it runs entirely in the browser on the workbook the viewer
opens (layout of the practice workbooks in `data/templates/`). The owner may be a
non-programmer: explain changes plainly and keep them small.

## Commands

- `npm install` — once (installs the two build-time tools: esbuild and read-excel-file; the page itself has no runtime dependencies to download).
- `npm run dev` — serves `src/` unbundled at http://localhost:5173 (browsers cannot load ES modules from file://).
- `npm test` — must pass before you finish. `npm run check` = build + test.
- `npm run build` — writes `dist/business-dashboard-demo.html` (single self-contained file) and `dist/site/index.html`.
- `npm run data` — repacks `data/*/business.json` into `src/data/layouts.generated.js` (column layouts and rules only, no records) and `data/templates/` into `templates.generated.js` (never edit those by hand).
- `npm run vendor` — rebuilds `src/vendor/read-excel-file.js` after upgrading read-excel-file.

To try the app, open a practice workbook from `data/templates/` on the "Open your Excel" page (or download it there).

## Map

- `src/core/` — pure logic shared by browser and tests: `metrics.js` (figures), `tasks.js` (suggestion rules), `scenario-tasks.js` (suggestions + stored decisions), `calendar.js`, `mapping.js` (columns → records + checks), `model.js` (record fields, task-rule catalogue), `dates.js`, `csv.js`.
- `src/data/workbook.js` — reads the viewer's `.xlsx` into a scenario: one snapshot, reporting date = latest dated event in the file. `src/data/scenarios.js` — the one business, `MY_EXCEL`; `loadScenario()` is null until a workbook is open.
- `src/vendor/read-excel-file.js` — generated by `npm run vendor` (MIT library, no Web Workers). `src/data/*.generated.js` — generated by `npm run data`. Never edit generated files by hand.
- `src/ui/pages/excel.js` — open / re-read / forget the workbook, practice-workbook downloads, the start page.
- `src/site-config.js` — site settings with classroom defaults. The build and `npm run dev` replace it with the GitHub repository variable `BUSINESS_NAME`, checked by `scripts/site-config.js`; `publish-site.yml` passes it in.
- `src/storage/local-state.js` — browser-local state (localStorage, memory fallback).
- `src/ui/` — `view-state.js` (filters + derived figures), `shell.js`, `router.js`, `components.js`, `drawers.js`, `pages/*.js`.
- `src/briefs/` — `brief-input.js` (facts text), `brief-facts.js` (number checker), `ai-prompt.js` (the Gemini request: fixed instructions with no numbers + the facts, name hiding, and `answerProblems()` for the answer), `gemini.js` (the only network access: "Analyse with Gemini" with the viewer's own key).
- `src/i18n/` — `tr()` plain text, `tl()` menu/button text as `中文（English）`; Chinese in `zh.js`.
- `data/` — test material: the synthetic BetterSpace training data (CSV, two businesses × two days) and `business.json` (layouts and rules); `data/templates/` holds the practice workbooks. `test/expected/` — answer keys. `test/support/training.js` loads the training data for the tests; the app never does.
- `LICENSE` — MIT, copyright Infinite New Media. Keep it (and the notice the build puts at the top of the built file); a student's own additions may carry their own name.

## Rules you must not break

1. **Figures come from the records.** Never hardcode a total, never read `test/expected/` or the training CSVs from `src/`. `test/metrics.test.js` and `test/workbook.test.js` reconcile the training data (CSV and practice workbooks) with the pack's `expected_metrics.json`; if they fail, fix the code, not the answer keys.
2. **The reporting date comes from the data.** Use `scenario.reportingDate` (the latest dated event in the workbook). Never use `new Date()` or "today" for a business date. Dates are `YYYY-MM-DD` strings; money is integer cents.
3. **No built-in business data.** The app bundles only column layouts and the practice workbooks — never records (`test/boundaries.test.js` checks the build). Do not edit files in `data/` unless the user explicitly asks; if they do, update `test/expected/` from an independent calculation.
4. **One network address, no keys in code.** The only request the app makes is `src/briefs/gemini.js` → `https://generativelanguage.googleapis.com`, when the viewer presses "Analyse with Gemini". Keep the Content-Security-Policy in `src/index.html` and `scripts/build.js` at `connect-src` that one host; no other `fetch`, external scripts, fonts, analytics or CDNs. The Gemini key is the viewer's own: typed into the page, stored only under `bd-starter.v1.gemini`, sent in the `x-goog-api-key` header. Never put a key in `src/`, the repository, repository variables (they are built into the public page — `scripts/site-config.js` refuses key-like values) or the build.
5. **Honest AI labelling.** Gemini answers are labelled "Live AI" with model and time, are number-checked with `answerProblems()` before the viewer reads them, and keep the privacy warning (Google's free tier may use what is sent; customer and staff names are replaced by codes by default). No fake loading or typing. Keep the request's instructions free of numbers.
6. **Stable task keys.** A suggestion's key is `rule:record_id` so decisions survive reading an updated workbook. Do not put dates or counters in keys. Decisions are stored separately from suggestions.
7. **The Excel stays local.** The workbook is read in the browser, stored only under `bd-starter.v1.workbook`, and never committed, uploaded or published. Its layout is the practice workbooks'; keep `test/workbook.test.js` passing. The reader must not use Web Workers or the network (the CSP blocks both).
8. **State stays per browser.** Keys start with `bd-starter.v1.`; "Clear decisions and notes" removes decisions and notes and keeps the file, the language and the key. If you change the stored shape, bump `STATE_VERSION` and keep reads defensive (stored data is untrusted).
9. **Every visible string is translated.** Wrap with `tr()`/`tl()` and add the Chinese to `src/i18n/zh.js`; `test/i18n.test.js` fails otherwise. Chinese is the default.
10. **Render text safely.** Use the `h()`/`t()` helpers (textContent). Never use `innerHTML` with data.
11. **Keep the look.** Colours come from the CSS variables in `src/style.css` (cream/wine/gold, validated for contrast). Gold is decoration only, never text. Check 375 px and 1366 px widths.
12. **Keep the labels honest.** The data is labelled as the viewer's own file, read locally; the practice workbooks as invented BetterSpace data. This is a learning starter, not a system for confidential business data.
13. **Settings are variables, not file edits.** Students set the business name with the repository variable `BUSINESS_NAME`; do not tell them to edit `src/site-config.js` or `business.json` for that. Values are built into the public page, so they must never hold secrets. Add any new setting the same way (checked in `scripts/site-config.js`, with a clear bilingual error).
